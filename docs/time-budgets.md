# Месячные лимиты часов

Лимит часов можно задать для **модуля** и для **проекта**. Расход считается по записям времени (worklog) за
календарный месяц в часовом поясе проекта. Когда расход достигает лимита, участники проекта (роль Member и выше) и
администраторы пространства получают одно уведомление за месяц. Новый месяц начинает отсчёт заново.

## Что считается

| Лимит | Что входит в расход | Настройки |
| --- | --- | --- |
| Модуль | всё, что ниже модуля: задачи модуля и (по умолчанию) их подзадачи до 5 уровней вложенности | «Учитывать подзадачи задач модуля» |
| Проект | всё, что ниже проекта: задачи в модулях и отдельные задачи, которые не входят ни в один модуль | «Задачи в модулях», «Отдельные задачи», «Подзадачи считаются вместе с родительской» (нужна хотя бы одна из первых двух) |

Время считается один раз, даже если задача связана с несколькими модулями или одновременно лежит в модуле и является
подзадачей другой задачи модуля. Проверка запускается при сохранении записи времени, при добавлении задачи в
модуль и при сохранении настроек.

## Где настраивается

- Модуль: боковая панель модуля, блок «Месячный лимит часов» (роли Admin и Member).
- Проект: **Настройки проекта → Лимит часов**. Просмотр доступен Admin и Member, изменение — администратору проекта.

API (сессия): `GET|PATCH /api/workspaces/<slug>/projects/<id>/time-budget/` и
`GET|PATCH .../modules/<id>/time-budget/`. Только чтение через публичный API и MCP (`get_time_budget`):
`GET /api/v1/workspaces/<slug>/projects/<id>/time-budget/` и `.../modules/<id>/time-budget/`.

## Уведомления

Уведомление о лимите приходит в раздел «Уведомления» (с тревожным значком на иконке и в списке новых задач при
наведении на неё). Для проекта и для модуля это отдельные уведомления; ссылка ведёт к настройкам лимита.

## Миграции

`0138_time_budget_scopes` добавляет поле `include_subtasks` у лимита модуля и таблицы `project_time_budgets` и
`project_time_budget_alerts`. Только добавления: старый код продолжает работать во время выкатки.
